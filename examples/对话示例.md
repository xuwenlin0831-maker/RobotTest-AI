# 对话示例

以下示例用于帮助团队理解 Skill 在不同输入条件下应该怎样表现。姓名、日期和枚举值均为示意，实际使用时必须替换为真实值。

## 示例一：信息完整，直接生成

用户：

```text
使用 $vehicle-testcase-lifecycle，按派生用例输出模式生成底盘状态灯测试用例。
来源资料是本任务中的 PRD 和 TB 模板。
编写人：张三
创建日期：2026-09-20
用例等级：P1
用例类型：功能测试
只生成本地 Excel 和评审清单，不上传 TB。
```

期望行为：信息完整，可以直接生成，不重复询问“是否确认生成”。

## 示例二：缺少编写人，停止生成

用户：

```text
使用 $vehicle-testcase-lifecycle，根据 PRD 生成底盘测试用例。
创建日期：2026-09-20
用例等级：P1
用例类型：功能测试
```

期望行为：不生成正式 Excel，集中列出缺失项，至少询问本批次编写人。

## 示例三：非必填字段未知

用户：

```text
所属分组和维护人暂时不确定，其他关键输入均已提供，请生成。
```

期望行为：未知的非必填字段留空，继续生成，并在评审清单中标注所属分组和维护人待人工确认。

## 示例四：用户要求上传 TB

用户：

```text
文件生成后直接帮我上传 TB。
```

期望行为：先生成并校验本地文件。上传前说明目标 TB 空间、文件范围和影响，取得新的明确授权后才能执行；当前 Skill 本身不提供 TB 上传能力。

## 示例五：用户要求增加状态列

用户：

```text
给模板增加“用例状态”，全部写待评审。
```

期望行为：说明当前 TB 标准模板固定为 17 列，用例状态不是模板字段，不增加第 18 列；若用户认为模板已变更，应先提供新版正式模板并走规则更新与验证流程。
