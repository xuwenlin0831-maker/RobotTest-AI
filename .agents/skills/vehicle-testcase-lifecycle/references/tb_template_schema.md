# TB 导入模板规则

> 规则版本：v0.2.0 ｜状态：待试用验证 ｜最后更新：2026-09-20
>
> TB 模板更新时，优先更新本文件，并按照 `tests/acceptance-checklist.md` 验证后再发布新 Skill 版本。

来源文件：`整车测试用例库_基础用例_导入模板.xlsx`

模板结构：

- 第 1 行：Teambition 导入规则说明，必须保留。
- 第 2 行：字段标题，必须保留。
- 第 3 行：示例记录，标记为“示例勿删”，必须保留。
- 第 4 行起：新增测试用例。
- 模板固定为 17 列，不得改名、调序或自行增加“用例状态”列。

17 列依次为：标题、所属分组、维护人、前置条件、步骤描述、预期结果、用例等级、用例类型、用例方法、创建日期、编写人、测试类型、备注、测试依据、测试设备、生产阶段、研发阶段。

## 字段映射

| TB 字段 | 生成约束 |
| --- | --- |
| 标题* | 对象、场景、预期行为；同一导入范围内唯一 |
| 所属分组 | 从一级分组完整填写，使用 `|` 分隔 |
| 维护人 | 非必填；填写时必须是 TB 企业内已存在成员 |
| 前置条件* | 执行前必须具备的状态或数据 |
| 步骤描述* | 一步一行，使用【1】、【2】编号 |
| 预期结果* | 与步骤编号一一对应 |
| 用例等级* / 用例类型* | 必须使用 TB 已配置的枚举值 |
| 创建日期* | 使用项目认可的日期格式和值 |
| 编写人* | 强制非空，必须是 TB 企业内已存在成员；默认整批使用同一人，除非用户明确提供映射 |
| 其他字段 | 依据项目配置填写；非必填字段未知时留空，并在评审清单中列明，不得虚构 |

## 用例状态

- 17 列模板没有“用例状态”字段，不得为写入状态而增加第 18 列。
- 不填写“用例状态”也可按当前模板导入 TB。
- 用例状态属于 TB 侧流程属性，不作为本 Skill 的生成字段、必填项或导入验收项；正式文件只需严格遵循 17 列模板。

## 生成前输入门槛

正式生成前必须确认：生成范围、来源资料、编写人、创建日期、用例等级、用例类型，以及足以形成标题、前置条件、步骤和预期结果的需求信息。

- 首次请求信息完整且明确要求生成或导出时，可直接生成。
- 缺少编写人或其他导入关键字段时，不生成正式 Excel，只集中询问缺失项。
- 非必填字段未确定时允许留空，并写入评审清单。

## 导入前检查

- 确认总记录数不超过 500。
- 检查所有必填字段、日期、成员、分组和枚举值。
- 检查第 4 行起每条用例的编写人均非空，且与本批确认值或用户提供的映射一致。
- 检查步骤和预期结果的编号完全匹配。
- 检查新增行没有破坏前 3 行或 17 列字段顺序。
