# RobotTest-AI 测试用例生命周期

## 定位

这是团队中唯一负责“标准 TB 用例输出”的 Skill。默认工作模式是生成项目 / 车型专属的派生用例；基础用例库治理必须由用户明确选择，并在人工授权下进行。

当前状态、版本、Owner 与发布记录见 [skill-registry.yaml](skill-registry.yaml)。TB 导入格式以 [TB 模板规则](references/tb_template_schema.md) 为准。

## 先确认工作模式

- **派生用例输出（默认）**：基础用例保持不动；根据 PRD、车型与配置生成复用、调整或新增的项目专属用例。
- **基础库治理（显式选择）**：仅输出基础用例的新增、修改、废弃建议与影响清单；不得未经人工授权直接改写基础库或 TB 数据。

## 正式生成前确认

生成可导入 Excel 前，必须具备明确的生成范围与来源资料，以及本批次适用的编写人、创建日期、TB 已配置的用例等级和用例类型。需求内容还必须足以形成标题、前置条件、步骤和预期结果。

- 编写人默认整批使用同一人；仅当用户明确提供逐模块或逐条映射时才使用多个编写人。
- 编写人必须是 TB 企业内的有效成员，不得留空、猜测或填写“待确认”。缺少编写人或其他导入关键字段时，集中列出缺失项并停止正式生成。
- 如果用户首次请求已经提供全部关键输入并明确要求生成或导出，可直接生成，不再重复要求“确认生成”。
- 非必填字段未确定时允许留空，并在评审清单中列出；不得虚构 TB 成员、分组、枚举值、验收结果或业务事实。

## 默认输出模式

1. 从 PRD 提取功能范围、车型 / 配置差异、交互、约束、验收条件与待确认项。
2. 参考基础用例和历史资产，判断每项需求是直接复用、调整、新增或待确认。
3. 编写一条只验证一个明确目标的用例；标题使用“对象 + 场景 + 期望行为”，步骤与预期结果按【1】、【2】逐条对应。
4. 按 TB 模板生成 Excel，并严格执行 [TB 模板规则](references/tb_template_schema.md)。
5. 同时提供评审清单，列出来源、变更理由、覆盖类型与待确认项。

正式文件固定保留 TB 17 列，不增加“用例状态”列。用例状态属于 TB 侧流程属性，不是本模板的生成字段或导入验收项；本 Skill 只按模板输出，不写入或推断用例状态。

## 两级确认

1. **正式文件生成**：按“正式生成前确认”检查。信息完整且用户已明确要求生成时，即视为第一级确认。
2. **外部动作**：上传 TB、发送文件或消息、修改任何外部系统前，必须说明目标、范围和影响，并取得新的明确授权。本 Skill 当前只生成和校验文件，不执行这些外部动作。

## 基础库治理模式

当用户明确选择基础库治理时，阅读 [基础库治理规则](references/base-library-governance.md)。AI 只输出变更建议包，不直接修改基础库或 TB 数据。

## 版本与发布

遵循 [版本策略](references/version-policy.md)。TB 模板变化时，先更新 `references/tb_template_schema.md`，用 `tests/tb-template-sample.xlsx` 验证，再在 `CHANGELOG.md` 发布新版本。未经验证不得声明新规则已可直接导入。

## 边界

- 可生成和校验 Excel；阶段一由人工审核、人工上传 TB。
- 生成本地文件不代表获得上传、发送或修改外部系统的授权。
- 自动创建 / 更新 TB 测试计划属于后续独立能力，不在本 Skill 当前范围。
- 其他 Skill 可以负责 PRD 结构化、基础库检索或 TB 上传，但不得维护第二份相互冲突的 TB 输出规则。
