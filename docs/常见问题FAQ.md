# 常见问题 FAQ

## 1. 这个 Skill 到底是干什么的？

它把团队对 TB 测试用例的编写规则、输入门槛、17 列模板结构和审核边界固化下来，让不同成员与 AI 对话时获得更一致、可评审、可导入的结果。

## 2. 有了 Skill，是不是一句话就能生成所有用例？

不是。Skill 统一流程和格式，但不会替代需求资料、业务判断和人工评审。输入信息不足时，它应该停止生成并追问，而不是凭空补全。

## 3. 每次对话怎么开始？

Codex 中建议先写：

```text
使用 $vehicle-testcase-lifecycle，按派生用例输出模式生成 TB 导入文件。
```

然后填写生成范围、资料、编写人、创建日期、用例等级和用例类型。

## 4. 为什么“编写人”必须填写？

因为当前 TB 导入模板把“编写人”作为必填字段。Skill 不允许猜测、留空或填写“待确认”；缺少时应停止正式生成。

## 5. 用例状态要不要写“待评审”？

不用。当前模板没有“用例状态”列，不填写状态也能导入 TB。Skill 必须保持原有 17 列，不得为了状态自行增加第 18 列。

## 6. 一个文件可以有多个编写人吗？

默认整批使用一个编写人。只有用户明确提供逐模块或逐条映射时，才使用多个编写人。

## 7. 不确定的字段怎么办？

导入关键字段不能缺失。非必填字段无法确认时可以留空，但要在评审清单里说明位置和原因，不能编造内容。

## 8. Skill 会自动上传 TB 吗？

不会。当前阶段只生成和校验本地文件。上传 TB、发送文件或修改其他系统前，必须重新说明目标、范围和影响，并获得明确授权。

## 9. Skill 会直接修改基础用例库吗？

不会。默认模式生成项目或车型的派生用例。只有用户明确选择“基础库治理”时，Skill 才输出新增、修改、废弃或保留建议，而且仍不直接改库。

## 10. Codex 和 ChatGPT 网页端都能用吗？

核心规则可以复用，但第一阶段主推 Codex。Codex 可从仓库 `.agents/skills` 读取完整 Skill；ChatGPT 网页端若未安装对应 Skill 或 Plugin，只能使用手动兼容提示词，约束可靠性依赖当前对话。

## 11. GitHub 链接是不是安装链接？

对 Codex 而言，成员可以克隆仓库后打开项目，或使用 Skill Installer 从仓库安装。对普通 ChatGPT 网页对话而言，单独粘贴 GitHub 链接不等于安装 Skill。

## 12. 什么是 Plugin？现在需要做吗？

Plugin 是可以安装和分发的工具包，可以包含一个或多个 Skill，也可以包含外部工具连接。当前规则仍在试用，先维护 Skill 即可；完成真实验证并需要网页端统一分发时再制作 Plugin。

## 13. 怎么确认这次真的使用了 Skill？

前期统一显式调用 `$vehicle-testcase-lifecycle`，并检查回复是否执行了输入门槛、17 列规则、编写人规则、评审清单和外部动作确认。如果这些行为缺失，应停止生成并反馈给维护人。

## 14. 谁对最终结果负责？

AI 负责生成候选内容和格式检查，编写人及评审人员负责业务正确性，实际上传者负责确认上传范围。Skill 不替代这些职责。

## 15. 当前版本可以直接用于生产批量导入吗？

当前状态是“规划中－待试用”。应先使用脱敏或非生产数据完成一次 TB 试导入，验证通过并记录结果后，再决定是否升级为已验证版本。
