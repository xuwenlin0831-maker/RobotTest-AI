# Codex 使用教程

## 适用对象

本教程适用于使用 Codex 桌面端、CLI 或 IDE 扩展，并希望基于统一规则生成 TB 测试用例的成员。

## 1. 获取项目

仓库发布后，从 GitHub 克隆：

```powershell
git clone https://github.com/xuwenlin0831-maker/RobotTest-AI.git
Set-Location -LiteralPath '.\RobotTest-AI'
```

也可以在 GitHub Desktop 中选择 `Clone repository`。如果仓库为 Private，需要先使用有权限的 GitHub 账号登录。

## 2. 在 Codex 中打开项目

在 Codex 中选择本地 `RobotTest-AI` 文件夹作为项目目录。仓库级 Skill 位于：

```text
.agents/skills/vehicle-testcase-lifecycle
```

Codex 会从仓库的 `.agents/skills` 目录发现 Skill。若刚拉取或更新后没有显示，重启 Codex或新开任务。

## 3. 显式调用 Skill

在新任务开头输入：

```text
$vehicle-testcase-lifecycle
```

建议团队前期都显式调用，便于确认本次使用了统一规则。熟悉后，即使不写 `$`，Codex 也可能根据任务描述自动选择 Skill，但不建议把自动匹配当作唯一保障。

## 4. 一次生成需要提供什么

正式生成前至少提供：

| 输入 | 要求 |
| --- | --- |
| 生成范围 | 明确模块、功能、车型或版本 |
| 来源资料 | PRD、需求说明、历史用例或其他依据 |
| 编写人 | 必填；TB 企业内有效成员；默认整批同一人 |
| 创建日期 | 项目认可的日期 |
| 用例等级 | 必须是 TB 已配置值 |
| 用例类型 | 必须是 TB 已配置值 |
| 需求信息 | 足以形成标题、前置条件、步骤和预期结果 |

缺少关键输入时，Skill 应停止正式生成，并一次性列出缺失项。非必填字段无法确认时可以留空，但必须列入评审清单。

## 5. 推荐提示词

```text
使用 $vehicle-testcase-lifecycle，按派生用例输出模式生成 TB 导入文件。

生成范围：隙锋 XX 模块 V2.0
来源资料：请读取本任务附带的 PRD 和历史用例
编写人：张三
创建日期：2026-09-20
用例等级：P1
用例类型：功能测试

要求：
1. 严格使用 TB 17 列模板，不增加“用例状态”列。
2. 保留模板前三行，从第 4 行开始写入用例。
3. 所有新增行的编写人填写“张三”。
4. 同时输出评审清单。
5. 只生成本地文件，不上传 TB，不发送文件，不修改外部系统。
```

其中的姓名、日期、等级和类型必须替换为本次真实值，不要照抄示例。

## 6. Skill 会怎样处理请求

1. 判断是默认的派生用例输出，还是用户明确选择的基础库治理。
2. 检查导入关键字段是否齐全。
3. 根据需求和历史资产判断复用、调整、新增或待确认。
4. 按 TB 17 列模板生成 Excel。
5. 输出评审清单，标注来源、变化、空白非必填字段和待确认项。
6. 在没有第二级授权时，停在本地文件阶段。

## 7. 人工评审重点

- 文件仍为 17 列，没有增加“用例状态”。
- 模板前三行未改变，数据从第 4 行开始。
- 编写人全量非空，且为本批确认值。
- 标题明确，一条用例只验证一个目标。
- 步骤和预期结果使用相同编号并逐条对应。
- 等级、类型、成员和分组确实存在于 TB。
- 非必填空白项已出现在评审清单中。

## 8. 更新 Skill

仓库管理员发布更新后，在本地仓库执行：

```powershell
git pull
```

然后查看：

- `.agents/skills/vehicle-testcase-lifecycle/CHANGELOG.md`
- `.agents/skills/vehicle-testcase-lifecycle/skill-registry.yaml`

规则版本变化后，应使用样例重新验证；完成真实 TB 非生产试导入前，不得把状态改为“已验证”。

## 9. 不会自动做的事情

- 不自动上传 TB。
- 不自动发送文件或消息。
- 不擅自修改基础用例库。
- 不猜测编写人、TB 成员或枚举值。
- 不因为用户提到“待评审”就自行增加模板列。
