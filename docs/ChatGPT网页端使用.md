# ChatGPT 网页端使用

## 当前定位

本项目第一阶段主推 Codex。ChatGPT 网页端用于临时兼容，不作为当前正式的项目式使用入口。

原因是当前仓库提供的是独立 Skill，尚未打包为 Plugin。普通网页对话仅获得 GitHub 链接，并不会自动加载仓库中的 `SKILL.md`、参考资料和 Excel 样例，因此不能默认认为它与 Codex 的执行约束完全一致。

## 两种网页端情况

### 已由工作区安装对应 Skill 或 Plugin

如果 ChatGPT 的 Skill/Plugin 选择器中已经出现 `vehicle-testcase-lifecycle`：

1. 在对话中使用 `@` 选择该 Skill。
2. 上传本次需求资料和 TB 模板。
3. 使用下方标准提示词。
4. 下载结果后人工检查，不授权自动上传 TB。

### 没有安装 Skill 或 Plugin

使用“手动兼容模式”：

1. 上传 TB 17 列模板和本次需求资料。
2. 把下面的标准提示词完整发给 ChatGPT。
3. 明确编写人、创建日期、用例等级和用例类型。
4. 生成后按照仓库验收清单人工检查。

手动兼容模式依赖当前对话中的提示词和附件，不等同于安装 Skill，换一个新对话后需要重新提供规则和资料。

## 网页端标准提示词

```text
请根据我上传的需求资料和 TB 模板生成测试用例。

生成范围：
编写人：
创建日期：
用例等级：
用例类型：

必须遵守：
1. 严格使用模板现有 17 列，不新增“用例状态”列。
2. 保留模板前三行，从第 4 行开始新增用例。
3. 编写人必须填写，不得猜测或填写“待确认”。
4. 缺少编写人、日期、等级、类型或必要需求信息时，停止生成并一次性列出缺失项。
5. 非必填字段不确定时留空，并输出评审清单。
6. 步骤和预期结果使用【1】【2】编号并一一对应。
7. 只生成可下载文件，不上传 TB，不发送给他人，不修改外部系统。
```

## 网页端必须人工检查

- 是否仍为 17 列。
- 是否保留前三行。
- 编写人是否全部填写。
- Excel 是否可正常打开。
- 步骤与预期是否编号对应。
- 等级、类型和成员是否为 TB 中真实值。

## 什么时候再做 Plugin

出现以下情况时再进入 Plugin 阶段：

- Skill 规则经过真实需求和 TB 非生产试导入验证。
- 团队需要在 ChatGPT 网页端统一安装。
- 需要把多个相关 Skill 作为一个工具包分发。
- 需要连接 TB、GitHub 或其他外部系统。

Plugin 属于后续发布能力，不改变“外部写入前必须再次确认”的原则。
