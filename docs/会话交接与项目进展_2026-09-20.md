## 2. 项目背景

项目名称为 **RobotTest-AI**。最初从“隙锋生产模块化测试”资料和现有用例库出发，希望逐步靠近更大的测试智能化方向。

第一阶段不处理完整基础库治理和 TB 自动集成，只聚焦一个可验证目标：

> 通过一份团队共用的 Skill，让不同成员与 AI 对话时，都能生成结构一致、符合 TB 17 列导入模板、可供人工评审的测试用例文件。

用户此前在组会上分享过 Skill，但组员对以下问题理解不足：

- Skill 到底解决什么问题；
- Skill 限制了 AI 的哪些行为；
- 安装后每次对话应该怎样开始；
- 缺少信息时 AI 应该怎么处理；
- Codex 和 ChatGPT 网页端如何使用；
- GitHub 链接、Skill 和 Plugin 之间有什么关系。

因此本轮除完善 Skill 外，还建立了 Codex 主教程、ChatGPT 网页兼容说明、FAQ 和对话示例。

## 3. 已确认的产品与使用方向

### 3.1 使用入口

- 主推 **Codex 项目式使用**。
- ChatGPT 网页端只提供简化兼容说明。
- 当前不制作 Plugin。
- 当前不自动上传 TB。
- 当前不自动发送文件或消息。

### 3.2 Skill 与 Plugin 的关系

- Skill 是针对具体工作流的可复用指令、参考资料、模板和可选脚本。
- Plugin 是可安装的软件包，可以包含一个或多个 Skill，也可以连接 MCP 工具和外部系统。
- 当前规则仍处于试用阶段，因此先维护 Skill；完成真实验证并需要在 ChatGPT 网页端统一分发时，再评估 Plugin。

### 3.3 仓库分发方式

- 使用 GitHub 作为当前代码和文档的版本来源。
- 仓库级 Skill 位于 `.agents/skills/vehicle-testcase-lifecycle`。
- 组员克隆仓库并用 Codex 打开根目录后，可显式调用 `$vehicle-testcase-lifecycle`。
- GitHub 链接对普通 ChatGPT 网页对话不等同于安装 Skill。

## 4. 当前 Skill 的正式规则

Skill 名称：`vehicle-testcase-lifecycle`

版本：`v0.2.0`

状态：`规划中-待试用`

### 4.1 TB 模板规则

- 正式输出沿用现有 TB 17 列模板。
- 第 1 行导入说明、第 2 行字段标题、第 3 行示例记录必须保留。
- 新增用例从第 4 行开始。
- 17 列字段名称和顺序不得改变。
- 不得自行增加第 18 列。

17 列依次为：

1. 标题
2. 所属分组
3. 维护人
4. 前置条件
5. 步骤描述
6. 预期结果
7. 用例等级
8. 用例类型
9. 用例方法
10. 创建日期
11. 编写人
12. 测试类型
13. 备注
14. 测试依据
15. 测试设备
16. 生产阶段
17. 研发阶段

### 4.2 关于用例状态的最终结论

- 当前模板没有“用例状态”列。
- 不填写用例状态也可以导入 TB。
- Skill 只按照现有模板输出，不写入、推断或验收用例状态。
- 即使业务希望导入后进入“待评审”，也不得为此擅自增加第 18 列。

### 4.3 编写人规则

- “编写人”是正式生成硬门槛，必须填写。
- 编写人必须是 TB 企业内有效成员。
- 不得留空、猜测或填写“待确认”。
- 默认一个输出批次使用同一个编写人。
- 只有用户明确提供逐模块或逐条映射时，才支持多个编写人。

### 4.4 正式生成前的关键输入

- 明确的生成范围；
- 来源资料；
- 编写人；
- 创建日期；
- TB 已存在的用例等级；
- TB 已存在的用例类型；
- 足以形成标题、前置条件、步骤和预期结果的需求内容。

处理规则：

- 信息完整且用户明确要求生成或导出时，可以直接生成，不重复索取“确认生成”。
- 缺少编写人或其他关键字段时，只集中列出缺失项，不生成正式 Excel。
- 非必填字段无法确认时可以留空，但必须进入评审清单。

### 4.5 两级确认

1. 本地正式文件生成：关键输入完整且用户明确要求生成，即视为第一级确认。
2. 上传 TB、发送文件或消息、修改 GitHub 或其他外部系统：说明目标、范围和影响后，重新取得明确授权。

## 7. 下一阶段调整后的优先顺序

原计划下一步直接开展完整试点。用户在本轮末尾调整为：先准备组内培训或讲解材料，再通过一个很小的 Demo 亲自试用并截图，将真实截图放入 PPT；完整试点随后进行。

推荐顺序：

1. 审核并确认 `docs/培训PPT大纲_RobotTest-AI_v0.1.md`。
2. 在另一个项目中使用 YOUIBOT 公司 PPT Skill 校验大纲。
3. 根据 `examples/最小Demo_状态灯用例生成.md` 运行双场景 Demo。
4. 截取“缺少编写人被拦截”“完整输入”“生成结果”“17 列检查”等画面。
5. 将确认后的截图和文字用于 HTML 审阅稿。
6. 用户明确确认 HTML 后，再生成正式可编辑 PPTX。
7. 培训材料稳定后，开展第一份真实需求 Excel 试点。
8. 在 TB 非生产范围人工试导入。
9. 邀请 1～2 名组员按照 GitHub 教程独立使用并补充 FAQ。
