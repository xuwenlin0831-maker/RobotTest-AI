## 一、需求简报

### 已知信息

- **目的**：让组内成员理解 RobotTest-AI Skill 的用途、约束、安装方式和一次正确对话应该怎样进行。
- **受众**：组内测试相关成员；此前接触过 Skill 分享，但对 Skill 的能力边界和使用方式理解不充分。
- **核心信息**：Skill 不是一个万能提示词，而是一套可复用、可版本化、带输入门槛和外部动作边界的标准工作流。
- **期望行动**：成员能够从 GitHub 获取项目，在 Codex 中调用 Skill，提供完整输入，人工检查生成结果，并理解当前不会自动上传 TB。
- **使用场景**：优先按组会或内部培训的现场讲解设计。
- **主入口**：Codex 项目式使用。
- **兼容入口**：ChatGPT 网页端简化说明。
- **当前成熟度**：`v0.2.0`，规划中－待试用；尚未完成真实 TB 非生产试导入。

### 本大纲采用的暂定假设

- 现场讲解约 20～25 分钟。
- 14 页，偏演讲型、低到中密度。
- 中文单语。
- 使用真实 Demo 截图，但必须隐藏账号、路径、内部需求和敏感数据。
- 添加简洁演讲者备注。
- 资料优先级：正式 Skill → TB 模板规则 → 验收清单 → README/教程 → 本轮对话总结。

### 正式制作前必须确认

- 正式标题、副标题；
- 演讲人、部门和日期；
- 实际培训时长和页数期望；
- 受众是否包含管理者；
- 是否内部保密；
- 是否允许出现“隙锋”项目名称；
- 是否需要演讲者备注；
- Demo 截图是否已经准备好。

## 五、演讲者提示

- 前半段不要先讲安装，先解释为什么需要 Skill 和它改变了什么。
- 用“缺少编写人时不生成”证明 Skill 不是普通提示词。
- 明确纠正“待评审需要写入 Excel”的误解：当前模板没有状态列。
- Demo 展示真实行为，不宣称当前版本已经完成 TB 生产验证。
- 最后一页只要求成员完成最小 Demo，不直接要求全员批量生产使用。
